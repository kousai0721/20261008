`CLAUDE.md` ができたら、次は **Inceptionフェーズの「ユーザーストーリー作成」から始める**のがおすすめです。

この段階では、まだコードを書かせません。最初に「何を作るのか」を固めます。

最初のプロンプトは、以下をそのまま使えます。

```text
## Inception - ユーザーストーリー作成

このプロジェクトでは、CLAUDE.md に記載された方針に従って
AI-DLCを実践します。

まず Inception フェーズとして、
開発対象のユーザーストーリーを整理したいです。

あなたの役割:
あなたは熟練したプロダクトマネージャーです。

目的:
開発対象について、
「誰が、何のために、何をしたいのか」を明確にし、
後続工程の契約となるユーザーストーリーと受け入れ基準を作成します。

以下のルールで進めてください。

- まだコードは作成しないでください
- 技術選定は行わないでください
- 開発言語、フレームワーク、DB、クラウドサービスなどはまだ決めないでください
- 私が明示していない要求や仕様を勝手に追加しないでください
- 不明点や判断が必要な点は質問してください
- ドキュメントは日本語で作成してください

まず作業計画を作成し、

aidlc-docs/inception/user_stories_plan.md

に保存してください。

計画の各ステップにはチェックボックスを付けてください。

私の説明や判断が必要な箇所については、
以下の形式で記載してください。

[Question]
質問内容

[Answer]

計画を作成した時点では、まだユーザーストーリーの作成を開始しないでください。

まず私に計画のレビューと承認を求めてください。

承認後、計画を1ステップずつ実行してください。

各ステップが完了したら、
user_stories_plan.md のチェックボックスを更新してください。

最終的なユーザーストーリーと受け入れ基準は、

aidlc-docs/inception/user_stories.md

に作成してください。

開発したいもの:
＜ここに今回作りたいシステムの概要を書く＞
```

最後の、

```text
開発したいもの:
＜ここに今回作りたいシステムの概要を書く＞
```

だけ、今回の題材に置き換えます。

例えばタスク管理アプリなら、

```text
開発したいもの:

個人向けのシンプルなタスク管理システムを作りたいです。
利用者がタスクを登録、確認、完了、削除できるものを想定しています。
```

くらいで十分です。

最初から細かく仕様を書きすぎない方が、今回のAI-DLC学習には向いています。Claude Codeに質問させて、人間が答える流れを体験できるからです。

実行すると、おそらくClaude Codeはまず、

```text
aidlc-docs/
└─ inception/
   └─ user_stories_plan.md
```

を作ります。

例えば中身は、

```markdown
# User Stories Plan

- [ ] Step 1: システムの目的と利用者を確認する
- [ ] Step 2: 主要なユースケースを確認する
- [ ] Step 3: 必要なユーザーストーリーを整理する
- [ ] Step 4: 受け入れ基準を作成する
- [ ] Step 5: 全体の整合性を確認する

## Questions

[Question]
このシステムは誰が利用しますか？

[Answer]

[Question]
複数ユーザーで利用しますか？

[Answer]
```

のようになるはずです。

ここで大事なのは、**まだ「進めてください」と言わないこと**です。

まず自分で `user_stories_plan.md` を確認して、

- 質問は妥当か
- 抜けている観点はないか
- AIが勝手に決めていないか
- 技術設計の話に踏み込んでいないか

を見ます。

問題なければ、質問に答えます。

チャットで答えてもいいですし、

```text
[Answer]
個人利用を想定しています。
```

のようにファイルへ直接書いても構いません。

その後、

```text
質問への回答を記載しました。
user_stories_plan.md を確認してください。

問題なければ、計画を承認します。
Step 1から1ステップずつ実行してください。

各ステップ完了後に、
何を行ったか報告してレビューを求めてください。
```

と送ります。

そして最終的に、

```text
aidlc-docs/
└─ inception/
   ├─ user_stories_plan.md
   └─ user_stories.md
```

ができます。

ここで一度、

```powershell
git status
git diff
```

を見て、問題なければコミットします。

例えば、

```powershell
git add .
git commit -m "docs: define user stories"
```

です。

その次は **新しいセッションに切り替えて Unit of Work** に進みます。

つまり、`CLAUDE.md` 完成後の最初の一連は、

```text
CLAUDE.md完成
    ↓
Gitコミット
    ↓
Claude Codeで新しいセッション
    ↓
ユーザーストーリー作成プロンプト
    ↓
user_stories_plan.md
    ↓
人間レビュー・回答
    ↓
承認
    ↓
user_stories.md
    ↓
人間レビュー
    ↓
Gitコミット
    ↓
/clear または新しいセッション
    ↓
Unit of Work
```

です。

今の段階では、**まず上の「Inception - ユーザーストーリー作成」プロンプトを投入するところまで進めればOK**です。
